# 会谈方案编排说明

本文面向负责设计、审核会谈方案的心理咨询与临床专家。专家通过文字向编排助手提出需求、确认调整方案并审核结果；修改与校验由助手负责，不要求专家阅读或修改代码。现状依据 2026 年 11 月 14 日的项目实现。

## 1. 快速上手

### 1.1 当前会谈方案

当前启用的是**经典认知行为会谈方案**，包含九个阶段：

**自由陪伴 → 情绪命名 → 情境澄清 → 自动化思维 → 认知歪曲 → 苏格拉底提问 → 替代性想法 → 行为激活 → 小结。**

首次从自由陪伴开始，小结之后返回情绪命名。目前每个阶段使用一轮对话后即进入下一阶段，没有启用条件停留或回退。“一轮”指一次用户输入及其对应的系统回复。

可调整的是**方案选择、阶段增删合并、先后顺序、阶段内容、话术风格、停留与回退规则**。风险评估、危机处理、热线和人工审核不通过会谈方案调整。

### 1.2 使用编排助手

在当前项目的 CodeBuddy 对话中，向助手提出以下请求：

> 请使用本项目的心理咨询会谈编排技能，协助调整会谈方案。先核对当前方案，再用临床语言说明拟修改的内容、完整阶段顺序、推进规则和影响范围。我确认后再执行修改，并报告校验与会谈验证结果。

随后提供第 1.3 节中的需求，或使用自己的临床表述。无需附上文件、程序名称或实现方法。如果助手无法找到项目技能，应由项目维护人员处理，专家不需要自行配置。

操作顺序为：**提出需求 → 审核变更方案 → 确认执行 → 检查结果 → 确认启用。** 需要保留现有方案时，应明确要求“另建方案，暂不启用”。助手只给出建议或文字说明，不等于已经完成修改；应以执行报告为准。

### 1.3 常用修改需求与表述样例

下列需求均通过文字交给助手。表中“助手应完成的操作”是专家审核结果的依据，不是要求专家自行实施。

#### 方案选择与阶段结构

| 修改需求 | 可直接使用的需求表述 | 助手应完成的操作 |
|---|---|---|
| 查看现状，不修改 | “请说明当前启用哪套方案，依次有哪些阶段，每阶段讨论什么，以及何时推进。暂不修改。” | 核对实际方案，列出完整顺序、内容和规则，不执行变更 |
| 切换已有方案 | “请展示现有焦点解决方案的完整流程和推进规则；保留原方案，待我确认后启用。” | 展示整套安排、说明切换影响，确认后切换，而不是只更改取向名称 |
| 新建方案，暂不启用 | “新建一套资源支持方案：关系建立、感受澄清、资源盘点、下一小步、小结。先提供各阶段目标和话术建议，不替换当前方案。” | 建立独立草案，待专家审核内容后完成修改和校验，保持当前方案启用状态不变 |
| 调整先后顺序 | “在当前方案中，将情境澄清放在情绪命名之前；其他阶段保持不变。请列出调整后的完整顺序。” | 调整相关阶段衔接，检查无遗漏或非预期循环，不只改变显示排列 |
| 增加阶段 | “在自由陪伴之后增加稳定化阶段，关注当下感受与可获得的支持，暂不讨论事件原因；先使用一轮，再进入情绪命名。” | 增加目标、主题、话术和避免事项，并接入指定位置 |
| 删除阶段 | “删除独立的认知歪曲阶段，自动化思维之后直接进入苏格拉底提问；其余安排不变。” | 删除阶段并处理原有衔接，核对保留内容是否仍连贯 |
| 合并阶段 | “将认知歪曲与苏格拉底提问合并为思维检视，保留思维模式辨识和证据讨论，安排在自动化思维之后。” | 整合两个阶段的内容，确定合并后的轮次和后续衔接供专家确认 |
| 修改首次阶段 | “新会谈从情绪命名开始，不再设置自由陪伴阶段；其他阶段顺序保持不变。” | 同时处理首次进入和阶段集合，验证新会话实际从指定阶段开始 |
| 修改小结后的返回位置 | “小结后返回自由陪伴，不再直接进入情绪命名；其他安排不变。” | 修改小结后的衔接，核对后续循环；不将返回开场误作结束会话 |

#### 阶段内容与表达方式

| 修改需求 | 可直接使用的需求表述 | 助手应完成的操作 |
|---|---|---|
| 修改阶段名称 | “将认知歪曲阶段的名称改为思维模式观察，内容和顺序暂不变。” | 仅修改对外名称；不将名称调整解释为内容或取向变更 |
| 修改阶段目标 | “情境澄清阶段以理解最近一次具体经历为目标，不分析成因、不评价他人。” | 修订该阶段目标，并检查主题和话术是否与新目标一致 |
| 增加或删除主题 | “情绪命名阶段增加身体感受的讨论，删除对情绪类别的列举；顺序和轮次不变。” | 核对现有主题，增加或移除相应内容；若原方案没有该主题，应如实说明 |
| 修改提问方式 | “苏格拉底提问阶段先反映用户的想法，再邀请讨论一个证据；不要连续追问。” | 修订该阶段回应与提问要求，不改变其他阶段 |
| 增加避免事项 | “行为激活阶段不要用布置作业或必须完成的措辞，先询问是否愿意讨论行动。” | 增加明确的避免事项，并检查话术中有无矛盾要求 |
| 修改通用风格 | “整套方案增加反映式倾听，减少直接建议，每次最多一个问题；阶段顺序不变。” | 修改全方案共同的表达要求，保持各阶段内容与之协调 |

#### 推进规则、启用与恢复

| 修改需求 | 可直接使用的需求表述 | 助手应完成的操作 |
|---|---|---|
| 固定使用两轮 | “情绪命名阶段连续使用两轮后，再进入情境澄清；其他阶段仍使用一轮。” | 同时设置持续轮数和上限，并验证第一轮后停留、第二轮后推进；不能仅增加上限 |
| 情绪强烈时停留 | “情绪命名阶段在系统评估的情绪强度达到 8 分时停留，最多使用两轮；未达到 8 分时，一轮后推进。” | 配置可执行的情绪条件和上限，报告命中、未命中及到达上限时的结果 |
| 调整已有上限 | “将情绪命名阶段现有条件停留的上限从两轮改为三轮，其他规则不变。” | 核对是否已有停留规则，只调整上限；若没有停留规则，说明单改上限不会延长阶段 |
| 设置条件回退 | “在行为激活阶段，若系统评估的情绪效价不高于负 0.6，下一轮返回情绪命名；当前回复也应先共情、不催促行动。” | 同时设置下一轮回退和当前轮话术要求，并说明到达上限时的处理 |
| 设置条件跳过 | “在替代性想法阶段，若系统评估的情绪强度达到 8 分，下一轮跳过行为激活进入小结；其他情况仍按原顺序。” | 设置指定条件与后续阶段，检查跳过行为激活后的内容衔接和上限优先级 |
| 确认启用 | “启用刚刚审核通过的方案。启用前请确认检查结果，并说明对已有会话的影响。” | 检查目标方案、说明影响，确认后启用并核对实际加载结果 |
| 恢复此前方案 | “恢复本次修改前保留的方案，先说明恢复后的阶段顺序，确认后再执行。” | 使用已保留的原方案恢复并核对；不能仅更改名称或声称自动撤销所有修改 |

以上是操作表述示例，不构成对临床顺序或阈值的推荐。合并、跳过、回退等修改应经专家审核。条件规则决定下一轮阶段；达到阶段上限时，系统优先按既定顺序推进，不再执行停留或回退。

## 2. 现有编排说明

### 2.1 每轮会谈如何执行

每轮先评估风险，再确定是否进入常规会谈。在默认设置下：

| 风险等级 | 会谈安排 |
|---|---|
| 无风险、轻度 | 按启用的会谈方案生成回复，并决定下一轮阶段 |
| 中度 | 进入安全计划并提供求助渠道，不推进常规会谈阶段 |
| 重度、危急 | 进入危机处理、求助渠道和人工审核，不继续探索性会谈 |

风险分流属于独立的安全管理。更换会谈取向或调整阶段，不改变这些安全要求。

进入常规会谈后，系统先按照当前阶段的目标、主题和话术生成回复，再根据推进规则决定下一轮继续、前进、回退或跳过。**一轮对话并不代表该阶段的临床目标已经完成**；当前系统也不自动以目标完成度决定阶段变化。

### 2.2 当前九个阶段的内容

| 顺序 | 阶段 | 目标与讨论内容 | 回应要求及主要避免事项 |
|---|---|---|---|
| 1 | 自由陪伴 | 了解希望讨论的事情以及当下情绪、身体感受 | 先回应感受，再开放式邀请；不立即分析或布置任务 |
| 2 | 情绪命名 | 澄清感受更接近难过、委屈、焦虑或疲惫，以及感受强度 | 使用用户自己的词复述并请其确认；不替用户定义情绪 |
| 3 | 情境澄清 | 了解最近一次出现感受的具体场景：何时、何地、与谁、发生什么 | 每次澄清一个事实要素；不追问创伤细节或评价他人 |
| 4 | 自动化思维 | 了解当时首先出现的想法与最担心的结果 | 邀请用户表达原有想法；不直接纠正或替用户补全 |
| 5 | 认知歪曲 | 温和辨识灾难化、全或无、读心、过度概括等思维模式及出现频率 | 邀请用户参与观察；不贴标签或直接断言其想法错误 |
| 6 | 苏格拉底提问 | 检视支持与不支持原想法的证据，探索其他解释 | 每次一个证据性问题，追问不超过两层；不争辩或连续施压 |
| 7 | 替代性想法 | 形成更平衡、更贴近事实的表达 | 由用户用自己的话表达；不强行积极化或否定痛苦 |
| 8 | 行为激活 | 在征得意愿后，讨论可完成的一小步、障碍和支持 | 行动具体、可执行；不命令、不设过高目标 |
| 9 | 小结 | 简要归纳会谈内容，询问有帮助或不适的部分 | 用两三句小结并邀请反馈；不长篇总结或代替用户评价疗效 |

全方案共同要求是先共情确认、一次只问一个问题、简短表达、不堆砌术语、不替用户下结论。目前九个阶段各使用一轮，小结之后返回情绪命名。

### 2.3 可供选择的已有方案

| 方案 | 默认阶段顺序 |
|---|---|
| 经典认知行为 | 自由陪伴 → 情绪命名 → 情境澄清 → 自动化思维 → 认知歪曲 → 苏格拉底提问 → 替代性想法 → 行为激活 → 小结；随后返回情绪命名 |
| 以人为中心 | 进入与安全 → 共情跟随 → 感受澄清 → 意义探索 → 自我接纳与资源 → 小结与反馈；随后返回进入与安全 |
| 焦点解决 | 目标建构 → 偏好未来 → 例外探询 → 量尺问句 → 赞许与资源 → 下一小步 → 小结与随访；随后返回目标建构 |
| 叙事 | 倾听问题故事 → 外化与命名 → 影响盘点 → 解构 → 独特结果 → 改写支线故事 → 见证与巩固 → 小结与反馈；随后返回倾听问题故事 |
| 动机式访谈 | 导进 → 聚焦 → 唤出 → 计划 → 摘要与反馈；随后返回导进 |

除经典方案外，其他已有方案包含部分停留或回退规则。切换前，应要求助手列出所选方案的完整规则。例如，焦点解决方案部分回退依据是系统评估的情绪数值，而不是直接识别用户是否愿意行动。

这些方案是项目示例，不等同于完整流派实施规范。适用人群、目标和具体话术仍需专家审核。

## 3. 可编排组件与能力边界

### 3.1 专家可以决定的内容

| 组件 | 专家需要决定什么 | 助手负责什么 |
|---|---|---|
| 方案选择与修订 | 使用哪套方案、是否另建方案、何时启用 | 核对现状，保留原方案，建立与切换方案 |
| 阶段集合 | 保留哪些阶段，新增、删除或合并哪些阶段 | 落实阶段变更，检查内容遗漏和衔接 |
| 阶段顺序 | 从哪里开始，先后次序，小结后返回哪里 | 调整完整路径，验证首次进入与后续循环 |
| 阶段内容 | 阶段目标、讨论主题、提问与回应方式、避免事项 | 将临床要求落实到各阶段，检查内部一致性 |
| 推进规则 | 固定轮数或条件推进，何时停留、回退或跳过 | 判断条件是否可实现，执行并验证规则 |
| 通用风格 | 整套方案共同的倾听和表达要求 | 修改共同要求，协调各阶段内容 |

修改名称不自动改变内容；更换取向名称也不等于启用另一套流程。提出名称调整与实质调整时，应分别说明。

### 3.2 停留、推进和回退

| 安排 | 含义 | 需求中应说明 |
|---|---|---|
| 按顺序推进 | 使用一轮后进入既定下一阶段 | 下一阶段是什么 |
| 固定轮数 | 在当前阶段连续使用指定轮数后推进 | 使用几轮，之后进入哪里 |
| 条件停留 | 条件满足时继续当前阶段，未满足则按顺序推进 | 条件、最多几轮、后续阶段 |
| 条件回退 | 条件满足时，下一轮使用之前的阶段 | 在哪个阶段判断、判断条件、回到哪里 |
| 条件跳过 | 条件满足时，下一轮直接进入指定后续阶段 | 跳过哪些阶段，转到哪里 |
| 循环 | 小结或其他阶段后再次进入指定阶段 | 返回位置及重复后的收束安排 |

**固定轮数与最多轮数不同。** “固定两轮”意味着正常进入该阶段后使用两轮；“最多两轮”只是上限，需要结合停留条件才可能使用第二轮。条件停留上限为两轮时，第一轮条件满足可继续，第二轮回复后即推进。

系统先检查阶段上限，再检查回退或跳过，再检查停留，最后按既定顺序推进。多条跳转条件同时满足时，采用预先约定的第一条；专家应审核优先次序。连续使用上限可设为一至十轮，但不能保证多个阶段反复回退的流程最终收束，因此循环也需单独审核。

回退规则在本轮回复后决定下一轮阶段。若希望当前回复避免推进技术，应同时提出话术要求，例如“先共情，不催促行动”，而不只要求回退。

### 3.3 条件可以依据什么

| 可用依据 | 专家可使用的表述 |
|---|---|
| 情绪强度 | “系统评估的情绪强度达到 8 分时停留。”强度范围为零至十分 |
| 情绪正负倾向 | “系统评估的情绪效价不高于负 0.6 时回退。”范围为负一至正一；负值偏负向 |
| 情绪唤醒程度 | “唤醒程度达到约定阈值时暂缓推进。”范围为负一至正一，与情绪强度不同；阈值需确认 |
| 会谈轮次 | “情绪命名连续使用两轮后推进”，或依据累计会话轮次判断 |
| 自述与表情、语音不一致 | “系统标记自述与表情或语音不一致时，下一轮回到情绪澄清。” |
| 已评估的风险等级 | 只能在允许进入常规会谈的范围内辅助安排，不能改变安全分流 |

专家可先提出临床意图，不必设计检测或实现方法。助手应说明该意图能否直接实现；需要阈值时，用临床语言请求确认，不得自行把“情绪较强”解释为任意数值。

当前不能直接以“用户愿意”“用户抗拒”“阶段目标已完成”自动决定下一阶段。这些要求可以作为话术原则，但尚不等于自动识别能力。助手不得未经说明，将“不愿意”替换成“情绪负向”作为判据。若现有能力不足，应报告限制并提交替代方案供专家选择。

### 3.4 不通过会谈编排调整的内容

| 需求 | 当前边界 |
|---|---|
| 更改风险判定或安全分流 | 属于独立安全管理，不能通过会谈方案修改 |
| 取消危机处理、热线或人工审核 | 不允许以流程体验或流派取向为由绕过 |
| 更改五分钟视频陪伴的阶段、时长或静默处理 | 使用独立流程，不能因修改常规会谈方案而自动生效 |
| 让模型自由决定任何下一阶段 | 当前不支持；只能按已审核的顺序和条件执行 |
| 小结后自动结束会话 | 当前返回开场不代表自动结束，方案没有自动结束会话的动作 |
| 为每位用户独立固定一套方案 | 当前启用设置共同生效，不支持按用户独立选择或固定版本 |

对于这些需求，助手应说明“不支持”“需另行开发”或“不允许”，不得以已完成普通编排代替能力说明。

## 4. 提出、确认和执行修改

### 4.1 专家的需求说明

一项需求通常包括以下内容。暂未确定的部分可以明确要求助手提出建议，不需要专家先补齐技术细节。

| 项目 | 说明 |
|---|---|
| 修改对象 | 当前方案、指定已有方案，或另建一套方案 |
| 调整目的 | 希望改善什么会谈问题，例如过早提问、行动要求偏强 |
| 阶段与内容 | 哪些阶段变化，各阶段目标、主题和话术要求 |
| 顺序与条件 | 放在什么位置，使用几轮，何时继续或回退 |
| 保留要求 | 哪些内容不变，是否保留原方案 |
| 启用要求 | 仅形成草案，还是审核后启用 |

完整示例：

> 请基于当前经典认知行为方案另建一套修订方案，保留原方案。在自由陪伴之后增加稳定化阶段，关注当下感受和可获得的支持，不追问事件原因。正常使用一轮；系统评估的情绪强度达到 8 分时继续，最多使用两轮，然后进入情绪命名。其他阶段顺序不变。请先列出完整安排和影响范围，待我确认后完成修改与校验，暂不启用。

### 4.2 修改前应收到的确认材料

助手应以临床语言提交以下信息，不要求专家提供或审核技术实现：

| 确认项 | 应提供的内容 |
|---|---|
| 当前安排 | 正在使用的方案与相关阶段规则 |
| 拟修改内容 | 新增、删除、合并、重排或话术变化的逐项清单 |
| 完整新流程 | 从首次进入到小结，以及小结后的返回安排 |
| 推进规则 | 固定轮数、条件、上限、跳转目标和优先级 |
| 能力限制 | 哪些临床意图不能直接自动判断，是否需要替代方案 |
| 影响与恢复 | 是否影响已有会话，如何保留并恢复原方案 |
| 安全影响 | 确认安全计划、危机处理和人工审核不被修改 |

专家确认的对象是这份会谈安排，而不是具体实现。仅查询现状时，助手不得执行修改。

### 4.3 确认后的执行

助手负责完成修改、检查阶段衔接和规则、核对启用状态，并提供测试结果。检查失败应由助手修正或报告阻碍，不应要求专家自行执行命令或修改代码。

建议先建立未启用的修订方案，完成审核和测试后再启用。启用前还应说明对已有会话的影响，并在会话空闲时执行。

如果直接修订正在使用的方案，修改完成后，后续会谈就可能采用新安排，不存在额外的待启用步骤。需要将修改审核与正式启用分开时，应明确要求“另建方案，暂不启用”。

**草案、修改完成、校验通过、已经启用是不同状态。** 助手应明确报告当前处于哪一步，不得把展示一段建议表述为已经生效，也不得把校验通过等同于临床审核通过。

### 4.4 启用后的影响

有效修改在后续对话中生效，不需要专家进行技术操作。但应注意：

- 修改未启用的方案，不会改变当前会谈；启用需要单独确认。
- 同一服务使用共同的启用方案，可能影响已有会话，不是只影响提出修改的专家或某位用户。
- 切换方案不会保证进行中的会话从开场重新开始；可能接续相同阶段，或返回新方案的开始阶段。
- 连续停留记录也不保证在切换时重置。核对首次进入和轮数时，应使用新测试会话。
- 应避免在一轮回复生成期间修改或切换方案，防止内容与阶段提示不一致。

这些影响由助手在启用前检查并说明，专家无需设计状态处理方法。

## 5. 结果审核与恢复

### 5.1 专家检查什么

助手完成后应提交完整新流程、修改内容、推进规则、启用情况和验证报告。专家重点检查：

| 检查项 | 专家应核对的结果 |
|---|---|
| 内容 | 回复是否围绕阶段目标，是否遵守话术与避免事项 |
| 顺序 | 阶段是否按审核通过的路径推进，是否存在遗漏或非预期循环 |
| 停留与回退 | 条件成立、不成立及到达上限时，是否得到预定结果 |
| 首次进入与小结 | 新会话从哪里开始，小结之后返回哪里 |
| 安全边界 | 常规编排没有改变安全计划、危机处理、热线及人工审核 |
| 启用情况 | 当前实际使用的方案是否就是审核通过的方案，而非仅建立了草案 |

可以要求助手：

> 请用新测试会话验证本次修改，并逐轮说明使用了哪个阶段、为什么继续或转入下一阶段。分别检查条件成立、条件不成立和达到上限的情况。请将已验证、未验证及需要人工审核的内容分开报告。

测试应使用虚构且不包含真实个人资料的内容，不以实际高风险用户作为流程测试对象。专家负责临床内容和适用性审核，技术检查由助手或维护人员执行。

### 5.2 如何理解界面的阶段提示

对话页回复后的阶段提示，可能已更新为下一轮使用的阶段。例如，本轮按自由陪伴生成回复，但回复后可能提示情绪命名。这不一定是内容与流程不符。

核对本轮内容时，应查看“决策轨迹”中的本轮来源阶段；也可以要求助手用中文逐轮解释“本轮做什么、下一轮去哪里、原因是什么”，不必自行分析技术记录。

### 5.3 恢复方案

修改前应要求助手保留原方案并记录修订内容。需要恢复时，可提出：

> 请恢复本次修改前保留的方案，先列出恢复后的完整流程和影响范围，确认后执行，并检查实际启用结果。

仅修改方案名称不能恢复内容，切换也不会撤销已改写的原方案。若没有保留副本，助手应说明能否可靠恢复，不能声称系统具有任意历史版本的自动回滚能力。

修改异常时，系统可能改用内置经典方案作为备用安排。助手应明确说明是否出现备用安排及原因，不能将会谈仍可继续视为新方案已经正确启用。

## 6. 职责与审核原则

| 角色 | 职责 |
|---|---|
| 临床专家 | 提出调整目的，决定阶段目标、内容和节奏，确认变更，审核临床适用性 |
| 编排助手 | 理解需求、核对现状、提交变更方案、执行修改、完成检查、解释结果和恢复方式 |
| 项目维护人员 | 处理技能不可用、权限或部署问题，以及现有能力之外的开发工作 |

本手册的操作以文字交互为默认方式，不要求专家提供实现方案。技术维护说明供维护人员单独查阅，不作为专家完成编排的前置条件。所有示例均用于说明操作，具体临床方案仍须经具备相应资质的专家审核后使用。
