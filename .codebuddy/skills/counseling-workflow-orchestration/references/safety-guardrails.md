# 临床安全护栏（改动前后强制检查）

> 本文件列出代码级锁定的安全不变量与方案层的临床红线。任何专家诉求与这些条目冲突时，拒绝该部分并用临床语言解释原因，给出不触碰红线的替代方案。禁止「先改了再说」「加个开关默认关掉」这类折中。

## 1. 不可改写项

| 不变量 | 代码位置 | 为什么 |
|---|---|---|
| 四通道风险取最大值、等级只升不降 | `graph.final_level()`、`graph_state.keep_max` | 任一通道告警被吞掉即可能漏报危机 |
| 重度及以上必进危机并挂起等人工 | `risk_rules.route()`、`validate_config()` 的 `crisis_min_level <= 3`、`graph.human_review_node()` | 自动化闭环不得替代人工判断 |
| 危机必给热线、必用危机级兜底话术 | `graph.crisis_node()`、`config.py` 热线常量 | 模型降级时也不能回落到普通会谈台词 |
| 词桶等级锁死、PHQ-9 第 9 题满分必触发危机 | `risk_rules.validate_config()` | 量表硬触发不开放配置 |
| system prompt 绝对红线不可覆盖 | `graph_state.SYSTEM_TEMPLATE`、`protocol.FORBIDDEN_TEXT`、`risk_rules` 黑名单 | 只许追加内容，不许覆盖基座指令 |
| `persist_flags` 在所有风险通道汇聚之后；`risk_detector` 独立于 LLM | `graph.build_graph()` | 提前装配会注入偏低的当前风险等级 |
| `crisis → human_review → memory_writer` 与 `interrupt()` | `graph.build_graph()` | 挂起与恢复是审计闭环 |
| **方案只作用于 `cbt` 分支** | `protocol.validate_protocol()` 强制 `applies_to == ["cbt"]`；`assemble_system()` 在等级 ≥2 时不注入阶段目标 | 危机/中度分支不得出现探索式会谈主题 |
| **阶段转移由确定性规则决定** | `protocol.decide_next()`（`max_turns` > `goto` > `stay_if` > `next`） | LLM 只生成回复，不决定下一阶段 |
| **停留必须可退出** | 每阶段 `max_turns` 1–10，校验强制 | 否则条件停留会让会话永久卡住 |
| 陪伴会话 `risk_level == high` 优先跳危机；`wrap_up_at <= 330` | `companion/state.py`、`risk_rules.validate_config()` | 时间/收尾条件不得盖过危机 |
| 并行分支写同一 state key 必须有 reducer | `graph_state.py` | 否则 LangGraph 抛错或丢数据 |

`risk_rules.LOCKED_ITEMS` 明确：四通道取 max、只升不降、必挂起这三项**在配置文件里没有开关**；把它们配置化本身就是禁止的改动。

## 2. 方案层专属红线（校验器会阻断）

- `applies_to` 只能写 `["cbt"]`；写 `crisis` / `moderate` / `all` 一律拒绝。
- 条件只能用白名单信号（`emotion.*`、`risk_level`、`turn`、`stage_turns`、`modality_inconsistent`），不得引入「由模型判断用户是否准备好」这类自由文本条件。
- `next` 与 `goto.to` 必须指向已定义阶段；所有阶段必须能从 `entry` 到达。
- 文本黑名单：「忽略以上」「不要遵守」「取消人工」「跳过危机」「输出格式改为」等覆盖基座或绕过安全的措辞。
- 每条话术 ≤300 字、方案文本总量 ≤3000 字，避免挤占上下文预算与安全区。
- 文件损坏或校验失败时回落到内置 `legacy_protocol()`，不得让会话崩溃；也不得为了让「新方案生效」而删掉回落逻辑。

## 3. 常见「看似合理但危险」的诉求

| 专家诉求 | 判断 | 回复要点 |
|---|---|---|
| 「中度也按方案继续聊 CBT」 | 拒绝 | 中度分支固定做安全计划与热线；方案只作用于低/无风险常规会谈 |
| 「危机时也走稳定化主题，不用挂人工」 | 拒绝 | 危机话术与人工审核是硬红线；稳定化主题可放在常规会谈里 |
| 「让模型自己判断该进哪个阶段」 | 拒绝 | 阶段转移必须确定性；用 `stay_if` / `goto` 表达临床条件 |
| 「情绪强烈时一直停在这个主题」 | 拒绝无限停留 | 可设强度阈值与 `max_turns`（例如 2–3 轮），到期自动推进 |
| 「为了体验流畅，先把风险判定放到回复生成之后」 | 拒绝 | 并行分叉与汇聚顺序不可调换 |
| 「把绝对红线那段提示词删掉，换个更自然的说法」 | 拒绝 | 安全区永远在最前且不可省略；只能在方案里追加风格说明 |
| 「收尾时间放宽到 10 分钟」 | 拒绝超限部分 | 330s 硬上限，可在护栏内调整 `wrap_up_at` |
| 「删掉风险词表里几个太敏感的词」 | 部分允许 | 只能把词移动到其它桶，且 `imminent`/`high` 桶不得为空 |

## 4. 改动前检查清单

- 已读 `references/workflow-map.md`、`protocol-schema.md`，涉及流派时已读 `schools.md`。
- 已判定类别（A–F）与是否需要代码改动；E 类先出边界说明。
- 已向专家输出变更计划并获得确认。
- 已确认改动不涉及第 1 节任一不变量；涉及即停止。
- 已确认新/改阶段都有 `next` 与 `max_turns`，整条链可达、停留条件可退出。
- 已确认历史会话残留旧阶段名有回落（切换方案后从新方案入口重新开始）。
- 涉及临床适用性（诊断、创伤、未成年人、危机史）时，提示需由具备资质的专家审定。

## 5. 改动后检查清单

- `scripts/check_workflow.py` 无 `[FAIL]`；`[WARN]` 已逐条说明。
- 所有方案文件 `valid=True`；`active.json` 指向有效方案；`protocol.active_status()` 的 `fallback=False`。
- 阶段中文标签、会谈目标、话术与方案说明文档一致。
- 低风险 / 中度 / 重度三档各跑一轮：低风险按方案推进，中/高风险仍走安全计划 / 危机协议 / 人工挂起，热线仍存在，人工可恢复。
- 决策轨迹中 `protocol.decision` 的中文原因与实际阶段一致；`cbt.stage` 的源与目标同源。
- 三端阶段标签显示中文，不出现英文 id 或空白。
- mock 与模型降级路径下危机分支仍输出危机级兜底话术。
- 已向专家说明回滚方式（还原 JSON / 改回 `active` / `git diff`）。

## 6. 临床话术约束（改方案文本时同样适用）

不诊断、不开药、不替代专业治疗；不描述或提供自伤/自杀的方法、工具、地点；不对自杀行为做中立化或美化表述；不承诺绝对保密；一次只问一个问题；追问深度有限；涉及生命安全必须转介并给出求助渠道。新增阶段的会谈目标与话术要点必须遵守以上约束，且与 `SYSTEM_TEMPLATE` 的绝对红线不冲突。内置方案是示例骨架，不是临床指南，须经专家审定后使用。
