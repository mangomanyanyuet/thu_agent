# 视频语音情绪识别陪伴助手 —— 产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 创建日期 | 2026-09-03 |
| 产品定位 | 心理健康筛查/陪伴类 AI Agent |
| 状态 | 草案，待评审 |

---

## 1. 背景与目标

本产品设计一个**视频语音对话 Agent**，扮演类似心理咨询师的角色，在**不超过 5 分钟**（时间可以适当宽松）的单次对话中，通过用户的**语音应答内容**与**摄像头捕捉的面部表情**，综合判断用户当前的情绪状态，并给出适度的共情反馈与建议。

**产品目标：**
1. 让用户在 5 分钟内完成一次自然、不生硬的"情绪对话"，获得一次情绪状态速览。
2. 通过语音语义 + 语音副语言特征 + 面部表情的多模态融合，提升情绪判断的准确性和鲁棒性（单一模态易受伪装、环境干扰影响）。
3. 在陪伴属性和安全边界之间取得平衡：Agent 提供情绪觉察与初步支持，但**不承担诊断、治疗职能**，遇到高风险信号时能够识别并妥善升级处理。

**非目标（明确不做的事）：**
- 不输出精神疾病诊断结论（如"你患有抑郁症"）。
- 不替代专业心理咨询/医疗，不进行长程心理治疗式对话。
- 不做面部身份识别/身份核验，仅做表情特征分析。

---

## 2. 术语与定义

| 术语 | 说明 |
|---|---|
| 情绪状态 | 本产品采用"维度 + 类别"双重表达：愉悦度(Valence)、唤醒度(Arousal)为连续维度；同时映射为若干离散情绪标签（如平静、焦虑、低落、烦躁、疲惫等） |
| 多模态融合 | 将语音文本语义、语音声学特征、面部表情特征在时间维度对齐后加权融合，输出统一情绪判断 |
| 风险信号 | 用户语言或表情中出现的自伤/自杀意念、极端消极等需要人工介入或资源转介的内容 |
| 会话轮次 | 一次 Agent 提问 + 用户回答，构成一轮对话 |

---

## 3. 产品定位与边界

- **角色设定**：Agent 以温和、专业、非评判的"倾听者"口吻出现，语气参考心理咨询师的**共情式倾听**风格（如 Rogers 人本主义取向的"无条件积极关注"），但对外明确标注为"AI 情绪陪伴助手"，不冒充真人咨询师、不使用医生/咨询师头衔自称。
- **功能边界**：仅做情绪状态的**筛查级**识别与轻度支持性回应，不出具诊断报告，不给药物或治疗建议。

---

## 4. 目标用户与典型场景

- 希望快速自我觉察情绪状态、缺乏时间/意愿进行长程咨询的个人用户。
- 使用场景示例：工作间隙的情绪 check-in、睡前情绪梳理、某个事件后的情绪复盘。
- 使用环境假设：手机或电脑摄像头 + 麦克风，用户独处、相对安静的环境，单人对话（非多人场景）。

---

## 5. 整体用户旅程

```
进入 → 开场白与破冰（约 30 秒）
   → 主体问答 3-4 轮（约 4 分钟，含追问与共情回应）
   → 结束语 + 是否需要资源转介（约 20-30 秒）
   → [后台] 生成本次情绪判断结果
   → [界面] 对话结束后，以文字形式在界面展示本次情绪小结（不在对话中口头播报）
```

Agent 在对话过程中**只负责倾听、追问、共情回应**，不在语音对话里口头总结情绪判断结果；情绪小结统一由界面在会话结束后以文字形式呈现（详见第 9 节）。总时长尽量控制在 **5 分钟以内**，超时自动进入收尾流程（见 7.1）。

## 6. 功能需求

### 6.1 会话时长与节奏控制

| 阶段 | 目标时长 | 说明 |
|---|---|---|
| 开场破冰 | 10-20 秒 | 固定开场白 + 1 个轻量暖场问题，同时完成摄像头画面质量/光线检测 |
| 主体对话 | 3.5-4 分钟 | 3-4 轮开放式提问，每轮包含"提问→倾听→简短共情回应/追问" |
| 结束语 | 10-20 秒 | 感谢 + 温和收尾，提示"稍后可在界面查看本次情绪小结"；如识别到风险信号则触发资源提示（见 7.5） |

> 说明：Agent 不在对话中口头输出情绪判断结果，情绪小结改由界面在对话结束后以文字呈现（见第 9 节），因此原"情绪小结"语音环节已取消，时长并入主体对话与结束语。

**技术要求：**
- 需要一个**会话时长控制器**，实时统计已用时间，在进入第 4 分钟时触发"收尾提醒"逻辑，引导对话自然收束，而非硬性掐断。
- 若用户在提问后长时间沉默（如 >8 秒无语音输入），Agent 应主动轻声确认（"不着急，你可以慢慢说"），而不是空等占用时长。
- **不按轮次硬截断**：3-4 轮只是节奏建议，不是终止条件。是否结束取决于用户——静默 ≥60 秒时先确认"看到你很久没回复了，这次先聊到这里吗"，再过 30 秒仍无回复才进入结束话术；用户中途回复则重新计时。

### 6.2 对话流程与话术设计

**角色设定 Prompt 要点：**
- 身份：AI 情绪陪伴助手，语气温和、缓慢、非评判，多用开放式问题，少用封闭式是非题。
- 原则：先共情后提问（Reflect → Ask）；避免连续追问造成压迫感；避免使用诊断性词汇（如"你这是焦虑症"）。

**话术模板示例：**

| 环节 | 示例话术 |
|---|---|
| 开场 | "嗨，很高兴今天能和你聊聊。接下来的几分钟，我想单纯听听你最近的状态，没有对错，你想到什么都可以说。" |
| 暖场问题 | "先随便聊聊——今天整体感觉怎么样？" |
| 引导追问 | "听起来这件事对你影响不小，能说说当时你是什么感觉吗？" |
| 共情回应 | "嗯，这确实是挺让人疲惫的一件事，谢谢你愿意告诉我。" |
| 常规收尾 | "谢谢你今天的分享，希望接下来的时间你能对自己好一点。今天的情绪小结整理好之后，你可以在界面上看到。" |
| 风险收尾（触发风险信号时） | 见 7.5 |

**追问策略：** 采用"开放提问 → 情绪词捕捉 → 针对情绪词追问一层"的两级深度，不做超过两层的连续追问，避免 5 分钟内话题过散。

### 6.3 多模态情绪识别方案

#### 6.3.1 语音模态

- **ASR 转写**：实时语音转文本，用于后续语义情绪分析与对话状态管理。
- **文本语义情绪分析**：基于转写文本做情感极性/情绪类别分类（可用大模型 few-shot 分类或微调的中文情感分类模型），提取关键情绪词、否定表达、消极自我评价等。
- **副语言声学特征**：语速、基频(pitch)均值与波动、音量、停顿时长与频率、语调起伏、颤抖/哽咽等声学特征，作为情绪唤醒度(Arousal)的重要补充信号（文本语义常反映情绪类别，声学特征更能反映情绪强度和真实性）。

#### 6.3.2 视觉模态（面部表情）

- **基础表情识别**：基于面部关键点/动作单元(AU)的表情分类模型，输出如高兴、悲伤、愤怒、惊讶、恐惧、厌恶、平静等基本类别的概率分布。
- **微表情/持续状态特征**：眼神接触频率、眨眼频率、嘴角/眉头细微变化、面部整体活跃度(expressiveness)，用于捕捉言语未直接表达但情绪状态相关的信号。
- **质量前置检测**：会话开始前检测光线、人脸是否可见、是否单人入镜，不满足条件时提示用户调整，避免识别结果失真。

#### 6.3.3 多模态融合与时序对齐

- 以对话轮次为最小时间单元，将该轮用户发言对应时间窗口内的语音文本情绪、声学特征、面部表情特征对齐。
- 融合策略建议采用**特征级 + 决策级结合**：声学与文本特征可在同一时间窗口做特征级拼接送入情绪分类模型；面部表情作为独立通道输出情绪概率，再与语音通道结果做**加权决策融合**，权重可根据模态置信度动态调整（如面部遮挡/低光时降低视觉权重）。
- 输出粒度：单轮情绪判断 + 全程情绪趋势曲线（用于最终小结）。

#### 6.3.4 情绪输出体系

采用"维度 + 类别"双表达：

- **维度**：愉悦度 Valence（消极 ↔ 积极）、唤醒度 Arousal（平静 ↔ 激动）。
- **类别标签（示例，可按场景裁剪）**：平静、愉悦、焦虑、低落、烦躁/易怒、疲惫、紧张、惊讶。

单轮输出示例（内部数据结构，非最终用户可见文案）：

```json
{
  "turn_id": 2,
  "timestamp_range": [45, 78],
  "text_emotion": {"label": "低落", "confidence": 0.62},
  "acoustic_emotion": {"valence": -0.3, "arousal": 0.2},
  "facial_emotion": {"label": "疲惫", "confidence": 0.55},
  "fused_emotion": {"label": "疲惫/低落", "valence": -0.35, "arousal": 0.15, "confidence": 0.58}
}
```

### 6.4 异常与边界情况处理

| 情况 | 处理方式 |
|---|---|
| 未授权摄像头/麦克风 | 提示用户仅能进行文本或纯语音模式，情绪判断精度会相应降级并告知用户 |
| 光线不足/人脸检测失败 | 提示用户调整环境，超过一定时长仍失败则降级为纯语音模式 |
| 用户中途退出 | 保存已产生的部分情绪快照，不做完整小结，友好告别 |
| 网络抖动/掉线 | 本地缓存已识别结果，恢复后尝试续接或直接进入收尾 |
| 多人入镜 | 提示"当前场景可能不适合个人情绪对话"，建议用户单独环境下重新开始 |

## 7. 非功能需求

- **实时性**：语音识别与情绪反馈延迟应控制在可接受的对话节奏内（建议单轮响应延迟 < 2 秒，避免打断对话自然感）。
- **准确性目标**：融合后情绪类别判断的一致性（与人工标注对照）作为核心评估指标，需在正式上线前通过标注数据集验证（具体目标值待与算法团队评审后确定）。
- **鲁棒性**：应对弱光、口音、语速过快/过慢、部分遮挡等场景有基本降级策略而非直接失败。
- **设备兼容性**：主流手机/PC 浏览器摄像头与麦克风兼容。
- **多语言**：首期支持中文普通话，后续可扩展方言/多语言。

## 8. 隐私、伦理与合规要求

- **知情同意**：会话开始前必须明确告知用户——本产品的性质（AI 工具，非专业医疗/咨询服务）、将采集的数据类型（音频、视频/面部特征）、数据用途与留存策略，用户需主动确认同意后方可开始。
- **数据最小化**：面部图像/视频建议仅做**实时特征提取**，不做原始视频长期存储；如需存储用于产品优化，需二次单独授权并做匿名化处理。
- **生物特征数据合规**：面部表情数据属于敏感生物特征信息范畴，需符合所在地区数据保护法规（如个人信息保护法等）的相关要求，明确告知并给予用户随时删除数据的权利。
- **未成年人保护**：需要有年龄确认机制，未成年用户建议限制使用或需监护人同意，并调整话术与风险处理流程。
- **免责声明文案（示例）**："本工具是一款 AI 情绪陪伴助手，通过分析你的语音和表情提供情绪状态参考，不能替代专业心理咨询或医疗诊断。如果你正经历持续的情绪困扰，建议寻求专业帮助。"

## 9. 输出与用户反馈设计

### 9.1 输出原则

- **对话中不做口头小结**：Agent 在 5 分钟对话过程中只负责倾听、追问、共情回应，不在语音里输出情绪判断结论，避免打断对话的自然感、也避免识别结果不稳定时口头表述带来的误导。
- **情绪小结改由界面文字展示**：对话结束后，由界面以文字形式呈现本次情绪小结，具体文案与视觉呈现属于 UI/前端设计范畴，本 PRD 约定后端需提供的数据接口与内容要素（详见 9.2）。
- 若情绪结果生成需要一定处理时间，界面应有合理的等待态提示（如"正在为你整理这次的情绪小结…"），避免用户以为流程卡住。
- 展示文案应避免生硬的数据化表达（如直接甩出百分比概率），建议以自然语言 + 可选的可视化（曲线/标签）呈现，具体文案风格由 UI 侧另行设计，需与本文档的角色语气（温和、非评判、非诊断）保持一致。
- **可选详细报告**：情绪趋势曲线、跨模态一致性等进阶指标作为可选的"深入了解"入口展示，而非默认展示；主报告只呈现结论性的、易理解的内容。
- **历史记录**：若产品支持多次使用，可提供情绪状态的历史趋势视图（需用户授权保存）。

### 9.2 结果数据框架（终稿）

结果数据统一分为 **3 个固定层级（Tier）**，每个字段有唯一、确定的归属，不再做"可选/视情况"的模糊处理：

- **Tier 1 · 用户主报告**：对话结束后界面默认直接展示的内容，构成"情绪小结"主体，字段数量克制（5 个）。
- **Tier 2 · 用户详情页**：用户主动点击"查看详情"后展开的进阶内容，不默认展示。
- **Tier 3 · 仅后端/风控**：不通过任何用户界面呈现，只用于算法迭代、人工复核与风险处理流程。

**字段清单：**

| Tier | 字段（key） | 类型/取值 | 定义 | 数据来源 |
|---|---|---|---|---|
| 1 | `dominant_emotion` | enum，见 6.3.4 情绪标签集 | 全程占比最高的情绪类别 | 分类结果聚合 |
| 1 | `mood_statement` | string（自然语言，1 句） | 基于 valence/arousal + 主导情绪生成的整体状态描述，如"今天的你整体比较平静，带一点疲惫" | 模板/生成式文案，由 Tier 2 数值驱动 |
| 1 | `secondary_emotion` | enum，可为 null | 占比第二的情绪类别，用于表达复合情绪 | 分类结果聚合 |
| 1 | `self_care_tips` | string[]，1-2 条 | 非诊断性自我关怀建议 | 规则/模板生成，基于 `dominant_emotion` |
| 1 | `duration_sec` / `turn_count` | int / int | 本次对话时长与轮次，作为报告的元信息 | 系统计时 |
| 2 | `avg_valence` / `avg_arousal` | float，各 −1.00～+1.00 | 全程融合后的愉悦度、唤醒度均值 | 融合模型输出，用于渲染情绪坐标图定位点 |
| 2 | `emotion_distribution` | object（标签→占比，和为 1） | 各情绪类别在全程中的占比 | 分类结果聚合 |
| 2 | `emotion_trajectory` | array，每项 `{turn_id, valence, arousal, topic_keyword?}` | 按轮次排列的情绪变化点，用于绘制曲线 | 每轮融合结果 |
| 2 | `key_shift_points` | array，每项 `{turn_id, topic_keyword}` | 情绪显著变化对应的话题关键词（不含原始对话文本） | NLP 话题抽取 |
| 3 | `valence_range` / `arousal_range` | [float, float] | 全程维度极值 | 融合模型输出 |
| 3 | `emotional_volatility` | float，≥0 | 情绪轨迹标准差，反映稳定性 | 计算得出 |
| 3 | `voice_face_consistency` | float，0～1 | 语音通道与面部通道判断的吻合程度 | 双通道结果比对 |
| 3 | `incongruence_flag` / `incongruence_note` | bool / string | 言语与表情明显背离时的标记与说明 | 规则判断 |
| 3 | `overall_confidence` | float，0～1 | 本次融合结果的整体置信度 | 融合模型输出 |
| 3 | `modality_availability` | object `{voice, face}`，各 0～1 | 语音/面部数据的有效采集占比 | 质量检测记录 |
| 3 | `degradation_notes` | string[] | 识别过程中发生的降级情况记录 | 系统记录 |
| 3 | `risk_triggered` / `risk_level` | bool / enum(`none`/`watch`/`high`) | 是否命中 7.5 风险规则及等级 | 规则判断 |
| 3 | `resource_suggested` | bool | 是否已触发资源转介提示 | 规则判断 |

**三条硬性规定：**

1. **Tier 1 是唯一默认展示内容**，界面不得在用户未主动点击的情况下展示 Tier 2/3 的任何数值。
2. **Tier 3 不通过产品界面呈现给用户**，仅用于风控分诊、人工复核和算法效果评估；例外情况——`degradation_notes` 非空时，允许界面用固定文案提示"本次识别环境不理想，结果仅供参考"，但不展示字段本身的数值或原始记录。
3. **`risk_triggered` 为真时，报告流程整体让位于 7.5 定义的关怀+资源转介流程**，不生成常规 Tier 1/2 报告内容。

### 9.3 数据结构（终稿）

后端在会话结束后，按上述三层分别打包返回，前端按层级决定渲染时机：

```json
{
  "session_id": "xxxx",
  "tier1_summary": {
    "dominant_emotion": "平静",
    "mood_statement": "今天的你整体比较平静，带一点疲惫。",
    "secondary_emotion": "疲惫",
    "self_care_tips": ["如果最近工作压力比较大，不妨给自己安排一点短暂的休息时间。"],
    "duration_sec": 272,
    "turn_count": 4
  },
```

## 10. 开放问题与后续迭代方向

- 情绪判断模型的具体选型（自研 vs. 第三方 API）与训练/评测数据来源需在技术方案阶段进一步细化。

- 是否需要与真人心理咨询服务/热线做转介对接，属于商业化与合规层面的后续讨论点。
