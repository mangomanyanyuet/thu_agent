# MindTrace 工作流编排技术说明

本文仅供编排助手和项目维护人员查阅，说明会谈方案与风险分流、会话状态和五分钟陪伴流程的实现关系。内容依据 2026 年 11 月 14 日的项目实现。

临床专家使用 `docs/会谈方案编排说明.md`，通过文字提出需求、确认调整方案并审核结果；不需要阅读本文、修改文件或设计实现。本文的字段、接口和命令说明是执行人员的技术参考，不是专家的操作步骤。

## 1. 快速上手

### 1.1 当前会谈流程

当前启用 `cbt_classic`，阶段顺序是：

**自由陪伴 → 情绪命名 → 情境澄清 → 自动化思维 → 认知歪曲 → 苏格拉底提问 → 替代性想法 → 行为激活 → 小结。**

小结之后返回情绪命名。当前经典方案不含条件停留或回退，每轮按当前阶段生成回复后，更新为下一阶段。

每轮先完成风险评估和分流。默认设置下，无风险或轻度风险进入会谈方案，中度风险进入安全计划，重度或危急风险进入危机处理与人工审核。会谈方案只参与常规分支。

### 1.2 可修改内容及操作位置

| 修改内容 | 操作位置 | 修改方法 |
|---|---|---|
| 启用方案 | `backend/protocols/active.json` | 将 `active` 设置为有效方案标识 |
| 阶段集合 | 目标方案的 `stages` | 新增、删除或合并阶段，并更新相关引用 |
| 阶段内容 | `label`、`goal`、`topics`、`prompts`、`avoid` | 修改名称、目标、讨论主题、话术和避免事项 |
| 阶段顺序与循环 | `entry`、各阶段的 `next` | 修改入口与后继连接；移动文件中的阶段位置不改变顺序 |
| 条件与轮次 | `rules.stay_if`、`rules.goto`、`max_turns` | 定义停留、跳转或回退条件及连续使用上限 |
| 全局表达要求 | `global_style` | 修改整套方案通用的风格要求 |

执行人员的技术流程为：核对专家需求 → 提交变更方案并获得确认 → 复制为独立方案 → 修改内容及连接 → 校验 → 经确认后启用 → 用新会话验证。专家的文字需求样例见专家手册第 1 节，确认与执行流程见第 4 节；技术操作由助手或维护人员承担。

有效文件在后续读取时自动加载，无需重启。同一配置目录的生效指针全局共享，不是按会话隔离的设置。当前没有图形化阶段编辑页面。

## 2. 工作流分层

| 层 | 职责 | 实现位置 | 修改方式 |
|---|---|---|---|
| 会谈方案 | 常规会谈阶段、内容、顺序和条件规则 | `backend/protocols/*.json`、`backend/protocol.py` | 编辑方案文件 |
| 长期对话图 | 并行评估、风险分流、安全计划、危机及人工审核链路 | `backend/graph.py`、`backend/graph_state.py` | 开发者修改代码并回归 |
| 风险参数配置 | 词表、评估阈值、合法范围内的分流门槛和部分节奏参数 | `backend/risk_rules.py` | 临床参数功能的试跑、发布和回滚 |
| 五分钟陪伴流程 | 同意、质检、开场、主体、收尾、危机和结束状态 | `backend/companion/*` | 参数调整或独立代码修改 |

方案文件不能编辑图拓扑、风险分流或陪伴相位。风险模块中可审核调整的参数，也不等于会谈方案中的可编排组件。

## 3. 长期对话图与风险分流

文字对话和小程序对话调用 `graph.run_turn()`。主要执行链路如下：

1. `entry` 载入上下文和已有状态。
2. 并行执行 `risk_detector` 与 `context_builder`，分别提供规则、量表、多模态信号及模型评估。
3. `persist_flags` 汇聚结果、装配系统提示并记录事实。
4. `risk_gate()` 选择 `cbt`、`moderate` 或 `crisis`。
5. 常规和安全计划分支进入 `memory_writer`；危机分支先进入 `human_review`，待人工恢复后再写入记忆。

| 默认最终等级 | 默认分支 | 行为 |
|---|---|---|
| 0 / 1，无风险 / 轻度 | `cbt` | 按启用方案生成回复并更新阶段 |
| 2，中度 | `moderate` | 安全计划与热线，不更新会谈方案阶段 |
| 3 / 4，重度 / 危急 | `crisis` | 危机话术与热线，随后挂起等待人工审核 |

风险等级汇总使用四通道最大值，并通过 `keep_max` 保持会话内只升不降。系统提示必须在风险汇聚之后装配；等级达到中度时不注入探索性阶段目标。

默认门槛为 `crisis_min_level=3`、`moderate_level=2`。风险配置可在合法范围内提高分流敏感度，例如让轻度进入安全计划或中度进入危机分支；不能让中度进入常规方案，也不能使重度绕过危机和人工审核。

## 4. 会谈方案的执行语义

### 4.1 文件加载与校验

`backend/protocol.py` 从 `PROTOCOL_DIR` 读取配置；未设置时使用 `backend/protocols/`。`active.json` 的 `active` 指定目标文件标识，文件修改时间变化会触发后续读取重载。

运行时校验包括：标识与文件名一致、必填文本有效、`applies_to` 为 `["cbt"]`、入口和引用存在、阶段可达、条件信号与比较符合法、轮次上限有效及文本预算和覆盖指令检查。加载或校验异常会回落到内置 `legacy_protocol()`。

`CBT_STAGE_GUIDE`、`CBT_NEXT`、`CBTStage` 及前端静态阶段标签保留为原始兼容基线；编辑这些静态表不是修改启用方案的方法。

### 4.2 回复生成与阶段更新

`cbt_node()` 先获取当前有效阶段，通过 `stage_block()` 注入该阶段内容并生成回复，然后调用 `decide_next()` 决定下一轮阶段。

决策优先级为：**轮次上限 → 第一个命中的条件跳转 → 条件停留 → 默认后继。**

- `max_turns` 是连续使用上限，不是默认固定轮数。没有条件时，一轮回复后即按 `next` 推进。
- 从计数 0 开始，停留条件持续命中且上限为 2 时，第 1 轮后停留，第 2 轮后推进。
- 上限命中后直接使用默认后继，不再检查回退或停留。
- `next` 为 `null` 表示返回入口，不代表结束会话。
- 决策在回复生成后执行，回退条件不能阻止当前轮已经生成的提问；当前回复的谨慎要求须写入阶段内容。
- 多阶段回退循环仍需人工审核退出条件；单阶段上限不能保证整个流程收束。

可用条件字段为 `emotion.intensity`、`emotion.valence`、`emotion.arousal`、`risk_level`、`turn`、`stage_turns`、`modality_inconsistent`。强度范围为 0–10，效价和唤醒度范围为 -1–1。没有意愿、抗拒或阶段完成度条件字段。模型参与情绪评估，但不直接输出下一阶段指令。

### 4.3 阶段初值、切换和已有会话

新会话默认阶段为 `none`。若启用方案包含该阶段，就使用它；不包含时才回落至方案 `entry`。因此单改 `entry` 不一定改变含 `none` 方案的新会话首阶段。

切换方案仅改变生效指针，不重置已有会话：旧阶段不存在时回落至新入口，同名阶段存在时继续该阶段。多个内置方案含 `wrapup`，切换后可能先执行新方案的小结。当前切换也没有显式清零已有停留计数。

应在会话空闲时切换，并以新会话验证。单轮处理没有固定配置快照，中途修改可能导致回复内容与返回元数据使用不同读取结果。

## 5. 观察与校验

### 5.1 返回字段和事件

| 字段或事件 | 含义 |
|---|---|
| `protocol_id`、`protocol_name` | 返回时读取的方案标识和名称 |
| `protocol_fallback` | 当前加载是否回落内置方案 |
| `cbt_stage`、`stage_label` | 回复生成后更新的阶段状态；发生推进时表示下一轮阶段 |
| `protocol.decision` | 本轮来源阶段、下一轮目标和决策原因 |
| `cbt.stage` | 阶段变化；来源与目标相同时不记录 |
| `graph.transition` | 风险分流路径 |
| `phase.transition` | 独立陪伴流程的相位变化 |

对话页和小程序优先使用后端中文标签，不需要为新增阶段修改标签表。核对本轮回复内容应查看 `protocol.decision` 的来源阶段，不能将回复后的标签误认为本轮生成阶段。

### 5.2 方案接口

| 接口 | 功能 |
|---|---|
| `GET /api/protocol` | 生效方案摘要、加载状态和可选方案校验结果 |
| `GET /api/protocol/{id}` | 指定方案内容及校验结果，不切换 |
| `POST /api/protocol/switch` | 医生权限切换，先校验目标文件 |

没有通过这些接口保存或编辑阶段内容的功能。查看运行服务的接口状态与执行本地命令可能使用不同部署配置，应核对实际 `PROTOCOL_DIR`。

### 5.3 校验和回归要求

```bash
PYTHONPATH=backend python3 -c "import protocol; items = protocol.list_protocols(); print(items); assert items and all(p['valid'] for p in items), '存在未通过校验的方案'"
PYTHONPATH=backend python3 -c "import protocol; print(protocol.active_status())"
python3 .codebuddy/skills/counseling-workflow-orchestration/scripts/check_workflow.py
```

方案应通过运行时结构校验；启用后标识应符合预期且 `fallback=False`。项目脚本还固定回归 `cbt_classic` 原始连接和 `sfbt` 的示例条件行为，合法修改这些内置文件也可能导致示例断言失败。推荐复制为独立方案，保留内置基线，不将示例回归失败直接解释为非法配置。

验证应涵盖实际回复内容、完整顺序、条件命中与未命中、上限及循环，并确认安全计划和危机人工链路未改变。格式和结构通过不代表临床审核通过。

## 6. 五分钟陪伴流程与安全边界

五分钟陪伴使用独立的 `SessionState.next_phase()`，主要顺序为同意 → 质检 → 开场 → 主体 → 收尾 → 结束，另有危机和中途退出状态。当前会谈方案没有接入这条流程。

默认目标时长 300 秒，收尾点 240 秒，硬上限 330 秒。静默处理使用 8 / 60 / 90 秒阶梯，用户开口重置静默阶段。部分时长读取临床配置，具体维护位置在 `backend/companion/state.py`、`engine.py` 和 `service.py`。

会谈方案不得改变以下安全不变量：四通道取最大值、风险等级只升不降、重度必经危机与人工审核、危机热线和安全兜底、风险汇聚后装配系统提示、系统安全要求。陪伴危机优先级与时长硬约束也不由常规方案编辑。
