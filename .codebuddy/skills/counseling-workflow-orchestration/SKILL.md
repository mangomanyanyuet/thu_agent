# 心理咨询会谈编排

## Overview

把临床专家的自然语言诉求（例如「按焦点解决的思路，先谈想要的未来，再找例外」「情绪特别强烈时先留在情绪命名」「这套方案更适合以人为中心，别给作业」）转换成 `backend/protocols/*.json` 中可编辑、可校验、可切换的**会谈方案**。方案决定「先聊什么、后聊什么、每个阶段聊什么内容、用什么话术、何时停留或回退」；风险判定与危机处理仍由代码红线负责，不进入方案。

专家只描述临床意图；文件定位、字段填写、校验、切换与验证由执行本 skill 的 agent 承担。

## 使用原则

- 把提问者当作临床专家，不当作工程师。禁止要求对方提供文件名、行号、字段名或代码片段；也不要向专家展示 JSON 细节，除非对方主动要看。
- 只用临床语言沟通：阶段名用中文，风险等级用「无 / 轻度 / 中度 / 重度 / 危急」，不说 `CBT_NEXT`、`risk_gate`、`applies_to` 等实现词。
- 先复述理解，再给「现状 → 变更后 → 影响范围 → 安全影响」变更计划，确认后才改文件。
- 把安全红线置于需求之上。触及不可改项时拒绝该部分，给出临床可接受的替代方案，不做折中削弱。
- 优先**编辑方案文件**，不改 Python 源码；只有诉求明确涉及风险分流、图拓扑或 5 分钟陪伴会话时才进入代码改动路径。
- 一次只处理一个诉求；跨多套状态机时拆分执行并分别汇报。
- 改动前读取项目地图与方案规范，改动后运行校验脚本；不凭记忆推断当前方案内容。

## 工作流

### 第 1 步：判定诉求类型

读取 `references/workflow-map.md`，按下表分类：

| 专家的说法 | 类型 | 落点 |
|---|---|---|
| 会谈主题、阶段顺序、先聊什么后聊什么、阶段话术、流派取向 | **A 会谈方案（主路径）** | `backend/protocols/*.json` |
| 何时停留、跳过或回退到某个阶段 | **A 会谈方案** | 方案中的条件与轮次上限 |
| 换一套方案 / 试用某个流派的方案 / 恢复默认 | **A 会谈方案** | `active.json` 或切换接口 |
| 风险词表、哪个等级进危机、静默多久、评估提示补充 | B 临床参数 | 前端调参页或 `/api/risk-rules/*` |
| 图的节点、分流目标、人工审核链路；5 分钟陪伴相位 | C 代码编排 | `backend/graph.py` / `backend/companion/*` |
| 询问现状、为什么这样走 | D 只解释 | 不改文件 |
| 让 LLM 自己决定下一阶段、把风险规则搬进方案 | E 禁止/需评审 | 先读安全护栏并说明边界 |

### 第 2 步：加载方案规范与流派知识

A 类诉求必须读取 `references/protocol-schema.md`；涉及流派、取向、会谈顺序或代表技术时，同时读取 `references/schools.md`。先读生效方案文件，确认「现在」的阶段顺序与主题，不要照内置默认方案臆断。

### 第 3 步：澄清临床意图

仅在信息不足时提问，一次最多三问，全部用临床语言：

1. 顺序与主题：想先聊什么、再聊什么，哪些主题要合并或删掉。
2. 每阶段内容：会谈目标、可聊主题、话术要点、本阶段应避免什么。
3. 推进条件：每轮固定推进，还是在情绪强烈/抗拒/目标未清晰时停留、跳过或回退；停留最多几轮。
4. 适用范围：只用于文字长期对话（方案默认），还是也想影响 5 分钟视频陪伴会话（**默认不支持，需另行代码改动**）。

专家说不清时给出两到三个临床方案让其选择，不自行替专家做临床决策。

### 第 4 步：输出变更计划

用表格向专家确认，禁止出现代码术语：

| 项目 | 内容 |
|---|---|
| 现在会怎样 | 例如「默认按认知行为顺序：情绪命名 → 情境澄清 → 自动思维……，每轮推进一格」 |
| 改完会怎样 | 例如「改为先谈想要的未来，再找例外与资源，最后约定一小步」 |
| 影响哪些会话 | 例如「只影响低/无风险的常规文字会谈；中高风险与人工审核不变」 |
| 安全影响 | 例如「不改变风险判定与危机处理」或明确指出冲突 |

等待确认后执行。D 类诉求到本步为止，不修改任何文件。

### 第 5 步：编辑方案（不改 Python）

读取 `references/change-playbook.md` 与 `references/safety-guardrails.md`，然后按以下顺序处理：

1. 修改现有方案，或复制 `_template.json` 新建方案文件（去掉下划线前缀、文件名与 `id` 一致）。
2. 填写每个阶段的中文名称、会谈目标、可聊主题、话术要点、避免事项与下一阶段；为停留条件设置轮次上限。
3. 需要切换生效方案时改 `active.json` 的 `active`，或调用 `POST /api/protocol/switch`；修改后下一轮对话即生效，无需重启。
4. 保持 `applies_to` 为 `["cbt"]`；不写覆盖红线、取消人工审核、跳过危机的措辞。
5. 不为新阶段改前端标签表：每轮响应已携带 `stage_label` / `protocol_name`，三端会自动显示中文。

### 第 6 步：校验并验证

在仓库根目录运行：

```bash
python3 .codebuddy/skills/counseling-workflow-orchestration/scripts/check_workflow.py
```

修复所有 `[FAIL]` 项；`[WARN]` 逐条说明。再确认生效状态：

```bash
PYTHONPATH=backend python3 -c "import protocol; print(protocol.active_status()); print([(p['id'], p['valid']) for p in protocol.list_protocols()])"
```

若改动涉及非默认方案，用一轮低风险对话验证阶段顺序与「决策轨迹」页的「方案决策」事件；必要时在文档中同步更新方案说明。

### 第 7 步：向专家汇报

用非技术语言给出：改了哪套方案、新的会谈顺序、在哪一端能看到、如何验证、如何恢复（改回 `active.json` 或用 git 还原文件）。附上校验结果的一句话结论。明确说明方案不影响危机处理与人工审核。

## 常见触发语句

- 「按焦点解决的思路编排：先聊想要的未来，再找例外，不要一上来分析问题成因。」
- 「我们更认可以人为中心，别给建议也别布置作业，跟着用户走。」
- 「情绪强度高的时候先停在情绪命名，最多停两轮再往下。」
- 「把认知歪曲放到澄清情境之前，并把它改成『一起看看这个想法像哪类陷阱』。」
- 「加一个稳定化主题，放在开场之后；用户情绪转负时要能退回来。」
- 「切回默认那套认知行为方案。」「为什么每次聊到小结又跳回情绪命名？」
